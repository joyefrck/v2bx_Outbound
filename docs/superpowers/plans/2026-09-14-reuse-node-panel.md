# 新增节点复用面板配置

**目标：** 新增节点从已有配置读取面板地址和 API Key，回车复用第一套，允许选择其他套或手动填写。

**设计：** `m_collect_nodes` 接收可选的已有配置路径，仅新增节点传入事务快照。`m_panel` 按地址与密钥成对去重，保持已有节点顺序，显示来源节点 ID，不显示密钥。无可用配置时进入原手动流程。新增时后续节点默认共用，重新生成配置维持原流程。沿用现有事务、校验和回滚。

**技术：** Bash、jq、Python unittest。

- [x] 在 `tests/test_nodes.py` 覆盖默认复用、批量共用、不同面板、同域不同密钥、手动输入、无可用配置、无效选择、取消及回滚；先确认默认复用用例失败。
- [x] 修改 `src/manager/config.sh` 的面板选择与收集入口，`src/manager/nodes.sh` 传入已有配置快照。
- [x] 更新原手动新增用例与 `tests/runtime_manager.py` 终端交互，更新 README 与管理工具版本。
- [x] 运行 `bash build.sh`，运行节点和向导测试，再运行 `python3 -m unittest discover -s tests -v`，检查 shell 语法、SHA256 和 `git diff --check`。

验收：回车选择已有配置后不出现域名和密钥输入；选择多套配置保留正确配对；原有节点及出口规则不变；取消、重复节点和服务失败不留下部分新增；首次配置仍可手动填写。仅修改当前分支工作区，不操作生产服务器。
